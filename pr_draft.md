# Масштабное обновление: Omnivisor, Рефакторинг Isolation и Глобальные улучшения

## 🌐 Глобальные изменения и Архитектура (Core)
* **Система кастомных исключений:** Создан файл `exceptions.py` для поддержки собственных ошибок. Реализовано исключение `NoLogChannelError` для обработки ситуаций, когда канал логов не настроен.
* **Глобальный обработчик ошибок:** В `main.py` добавлена обработка `app_commands.AppCommandError`. Теперь при вызове `NoLogChannelError` бот отправляет красивый Embed с подсказкой использовать команду `/set_log`.
* **Очистка логики:** Коги `omnivisor`, `isolation`, `debug` и `messaging` теперь пробрасывают `raise NoLogChannelError()` во внешний обработчик, избавляя локальный код от дублирующихся проверок.
* **Интерактивная справка:** Команда `/help` полностью переработана. Теперь это удобное выпадающее меню с категориями команд, их описанием и автоматическим скрытием админ-модулей от обычных пользователей.
* **Увеличение таймаутов UI:** Время жизни интерактивных элементов (пагинация в изоляторе, меню справки) увеличено с 3 до 10 минут для комфортного чтения без спешки.
* **Рефакторинг системы проверки прав (DRY):** Создано кастомное исключение `AdminAccessDeniedError`. Теперь проверка прав (`check_admin_interaction`) централизованно выбрасывает ошибку, которая изящно перехватывается глобальным обработчиком в `main.py`. Это позволило полностью вычистить десятки строк дублирующегося кода с проверками из команд во всех административных когах проекта.



## 📨 Обновление модуля `Messaging`
* **Умная маршрутизация и ветки:** Команды теперь поддерживают прямую отправку в ветки (Threads) и голосовые чаты. Добавлен параметр `channel_link` для удобного указания целевого канала по ссылке.
* **Ответы на сообщения:** В команду `/send_msg` добавлен параметр `reply_on`. Если прикрепить ссылку, бот **сам** найдет нужный канал или ветку и ответит на сообщение. Ручной выбор канала через выпадающий список стал опциональным.
* **Новые параметры Embed:** В команду `/send_embed` добавлен "Бустерский" цвет (`#cd4ce4`) на случай редакции бустерского сообщения, а также добавлена возможность отключить отображение времени (timestamp).
* **Единый стиль логов:** Журнал действий приведен к стандарту (используются термины "Участник", "Модератор").

## ⭐ Обновление `StarChannels`
* **Умные названия веток:** Теперь бот не создает десятки одинаковых веток "Обсуждение [Никнейм]". В название ветки автоматически подтягивается первая строчка текста из сообщения (до 50 символов) и ник автора, что делает навигацию по каналам гораздо удобнее.

## 🚨 Обновление модуля `Reports`
* **Единый стиль команд:** Команды управления каналами переименованы для удобного поиска через слеш-меню Discord (`/report_add`, `/report_remove`, `/report_list`).

## 👁️ Внедрение системы `Omnivisor`
### 📝 Обзор
Добавлен совершенно новый глобальный модуль аналитики и безопасности. `Omnivisor` берёт на себя задачи по профилированию новых участников, ведению единого журнала действий модераторов и генерации отчетов.

### 🚀 Ключевые функции
* **Система оценки подозрительности (Threat Scoring):** Алгоритм `evaluate_suspicion` анализирует возраст аккаунта, тип аватара, значки профиля и совпадение никнейма с паттернами ботов. При критическом пороге генерируется алерт с кнопками быстрого реагирования.
* **Единая база данных SQLite:** Структурированная таблица `action_logs` фиксирует входы, выходы, кики, баны и изоляции. Команда `/omnivisor_sync_db` создает статический слепок текущего состояния сервера для Протокола-ξ.
* **Отчетность и экспорт:** Генерация файлов Excel (`.xlsx`) "на лету" с помощью `openpyxl`. Формат дат в статистике исправлен на точный (`<t:...:d>`) для удобства выгрузки.
* **Периодические отчеты:** Добавлен режим автоматической отправки статистики и отчётов, в том числе функция рассылки отчёта напрямую в ЛС администраторам.
* **Гибкая настройка:** Команда `/omnivisor_settings` управляет пингами, интервалами авто-отчетов и правами "на лету" (включая тумблер `auto_stat_enabled`).
* **Оптимизация (Cache-first):** Бот сначала обращается к внутреннему кэшу (`get_member`), минимизируя тяжелые запросы к API (`fetch_member`).

## 🛠 Рефакторинг модуля `Isolation`
### 📝 Обзор
Полная переработка системы изоляции участников. Основной упор сделан на унификацию кода, переход на асинхронную работу с данными и повышение стабильности при взаимодействии с Discord API.

### 🚀 Ключевые улучшения
* **Асинхронная работа с данными:** Переход на `aiofiles` и `asyncio.Lock()` для работы с `isolated_users.json`, что полностью исключает блокировку основного потока. Внедрен дата-класс `IsolatedUser`.
* **Интерактивная пагинация:** Команда `/isolate_list` теперь выводит список нарушителей страницами (по 10 человек) для обхода лимитов Discord. Кнопки работают 180 секунд и защищены от нажатий чужими пользователями.
* **Умный автокомплит:** Команда `/unisolate` динамически ищет пользователей по ID или никнейму прямо по базе изолятора, предотвращая опечатки.
* **Защита от обхода (Evasion Prevention):** Обработчик `on_member_join` автоматически распознает изолированных участников при их перезаходе на сервер и возвращает им роль изоляции.
* **Синхронизация при банах:** Если изолированный пользователь получает пермабан (`on_member_ban`), система автоматически вычищает его запись из JSON-базы.
* **Усиленная безопасность:** Запрещена изоляция системной роли `@everyone` и ролей, находящихся в иерархии выше роли бота. Бот корректно блокирует попытки изоляции администраторов и самого себя.
* **Единый стиль и фиксы:** Тексты логов и Embed-сообщений приведены к единому стандарту ("Участник", "Модератор", "возвращён"). Исправлена критическая ошибка при снятии изоляции.
* **Отдельный канал изолятора (`isolator_channel`):**
  * В команду `/isolate_settings` добавлен опциональный аргумент `isolator_channel` для настройки выделенного текстового канала изолятора.
  * Обновлено информационное меню `⚙️Сохранённые настройки`: теперь оно корректно отображает заданный канал изолятора и форматирует список изменений при обновлении параметров.
* **Проверка на бота (`isolate_as_bot`):**
  * В команду `/isolate` добавлен опциональный параметр `isolate_as_bot` (Да/Нет).
  * Если выбрано "Да", бот автоматически меняет причину изоляции на "Подозрения, что бот." и отправляет сообщение-проверку с пингом пользователя в настроенный `isolator_channel`, чтобы подтвердить, что перед нами реальный человек.
  * Добавлен защитный механизм, предотвращающий краш команды при попытке отправить проверочное сообщение, если канал изолятора не был настроен или был случайно удален с сервера.
